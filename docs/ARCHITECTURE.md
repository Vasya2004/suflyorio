# Архитектура

## Слои

- `Models`: SwiftData-модели Script, PromptSettings, Take. Одно локальное хранилище; ролики не помещаются в базу.
- `Core`: ScrollClock, RecordingState, TakeFiles и MovieValidation. Совместимы с macOS для проверок без iPhone.
- `Services`: CameraService, RecordingModel, LibraryStore, PhotoExporter.
- `Views`: библиотека, редактор, настройки чтения, камера, UIKit-прокрутка и просмотр дублей.

Сторонних зависимостей у приложения нет. Swift Package использует те же файлы для тестирования на Mac. Xcode-проект включает все исходники напрямую в модуль Sufler. Swift 5 language mode со строгой проверкой concurrency выбран для совместимости делегатных API; проект использует SDK iOS 26+.

## Запись и потоки

`RecordingModel` и `LibraryStore` работают на MainActor. `CameraService` изолирует конфигурацию, начало/конец записи и все изменяемые свойства последовательной DispatchQueue. Пометка `@unchecked Sendable` относится только к этому сервису и опирается на данную изоляцию. Извне доступен лишь неизменяемый объект session для слоя превью; UI не конфигурирует сессию.

Последовательность: разрешения → настройка камеры → ready → countdown → starting → подтверждение didStart → recording → finishing → проверка файла → review. Контролы смены камеры/сценария заблокированы до завершения; повторные события start/stop отбрасываются автоматом состояний. Запрос stop в состоянии starting сохраняется на очереди камеры и выполняется даже при позднем didStart.

Прокрутка начинается только при переходе starting → recording, рассчитывается через монотонные timestamps CADisplayLink. Пауза, декелерация, ручная перемотка и большие временные разрывы сбрасывают временную точку отсчёта. Окончание текста останавливает только прокрутку. Сам display link при паузе приостановлен.

Камера останавливается и освобождает аудиосессию перед выдачей результата, чтобы AVPlayer мог включить режим воспроизведения. Временный уход в inactive при системных запросах разрешений не отменяет первоначальную подготовку. Уход из активной съёмки останавливает дубль; ограниченная фоновая задача позволяет системе завершить файл, но не продолжает съёмку в фоне.

## Файлы и восстановление

1. До старта атомарно сохраняется TakeIntent: UUID, заголовок и дата. Имя видео выводится из UUID, а не из пользовательского текста.
2. В SwiftData создаётся Take со статусом pending, выполняется явный save. Ошибка запрещает старт.
3. AVCaptureMovieFileOutput пишет непосредственно в постоянный каталог, не в очищаемый tmp.
4. MovieValidation асинхронно проверяет локальный файл. Даже callback с ошибкой может содержать пригодный частичный ролик. Непустые видео- и аудиодорожки обязательны; их наличие не заменяет физическую проверку качества звука.
5. Только после проверки файл получает статус ready. Запись SwiftData подтверждается отдельно. Файл/журнал сохраняются при ошибке базы.
6. При запуске просматриваются журналы и бесхозные `.mov`; пригодные записи восстанавливаются, отсутствующие или повреждённые помечаются unavailable. Восстановление идемпотентно. До конца проверки заблокированы съёмка и действия с дублями.

Ролики удаляются только явно из библиотеки с подтверждением. Экспорт в Photos не перемещает оригинал, а добавляет копию. Удаление приложения удалит sandbox, поэтому важные ролики нужно экспортировать.

## Пределы первой версии

Только портретная ориентация, фронтальная/основная широкоугольная камера, 1080p/30, SDR, встроенный микрофон. Смена камеры доступна только до дубля. Bluetooth/USB-микрофоны, голосовая прокрутка, монтаж и облачная синхронизация не реализованы.

Идентификатор приложения зафиксирован в проекте, личная Team не включается в исходники. В репозитории нет сертификатов, паролей или provisioning profiles.
